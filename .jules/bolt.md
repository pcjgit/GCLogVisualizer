## 2023-10-25 - [Date Object Allocation in Massive Loops]
**Learning:** In massive processing loops (like parsing 500,000 GC log lines), instantiating `new Date()` for every item creates significant garbage collection overhead, heavily blocking the main thread. Attempts to extract time strings directly from ISO formats (e.g. `substring(11, 19)`) to avoid Date parsing failed because they extract UTC time, while `Date.getHours()` correctly extracts Local time.
**Action:** Always reuse a single `Date` object initialized outside the loop (`const reusableDate = new Date();`) and update it in-place inside the loop (`reusableDate.setTime(parsedTime);`). This maintains exact local timezone logic while reducing 1M+ object allocations to just 1.
## 2024-05-24 - [Log Parsing Loop Timestamps Optimization]
**Learning:** When parsing large sequential log files, many consecutive lines share the exact same raw timestamp string because multiple events happen within the same millisecond or second. Calling `Date.parse()` and running formatting string operations (e.g. padding and formatting hours/minutes/seconds) repeatedly on the exact same string causes unnecessary allocation overhead and performance bottlenecks.
**Action:** Implementing a simple "last seen" cache variable inside the parsing loop (`lastTimeStr`, `lastTimeValue`, `lastTimeLabel`) allows the code to bypass the expensive date parsing logic completely for grouped log entries, significantly speeding up the overall file parse.
## 2024-05-24 - [Manual Substring Parsing vs V8 Split]
**Learning:** Attempted to optimize massive log file parsing by replacing `fileContent.split('\n')` with manual `indexOf('\n')` and `substring()` loops to avoid allocating 500,000 string objects. Surprisingly, this was slightly slower (1.15s vs 1.11s). V8's native C++ implementation of `split()` is highly optimized for splitting huge strings when memory is available, and the overhead of executing JS string manipulation inside a tight 500k iteration loop outweighs the array allocation penalty.
**Action:** Do not attempt to manually re-implement native string splitting algorithms in JavaScript to avoid allocations unless running in extremely memory-constrained environments where `split()` causes an Out Of Memory crash.
